## 질문 1 — 프론트엔드 기술
V1 UI를 어떤 방식으로 만들까요? (학습 친화 NFR-6 고려)

A) 프레임워크 없이 TypeScript + Vite (바닐라 DOM) — 의존 최소, 구조가 투명해 학습에 유리

B) React + Vite — 컴포넌트 패턴 표준적이나 의존/빌드 개념 추가

C) 프레임워크·번들러 없이 순수 HTML+JS(ESM) — 가장 단순하나 TS/코어 import 처리 번거로움

X) 기타 (아래 [Answer]: 뒤에 설명해 주세요)

> 🤖 **프론트엔드 엔지니어 권장**: A) TypeScript + Vite (바닐라 DOM)
> **근거**: 각 보기 검토 — A는 Vite가 shared-core의 상대경로 TS import·번들·개발서버를 바로 처리(Q2/Q8 결정과 정합)하고 프레임워크 추상화가 없어 "DOM을 이렇게 그린다"가 코드에 그대로 보여 학습에 최적(NFR-6). B(React)는 컴포넌트 재사용엔 좋으나 상태관리·JSX·추가 의존이 학습 초점을 흐리고 프로토타입엔 과함. C는 의존이 가장 적지만 TS 타입·코어 import를 브라우저에서 직접 처리하기 번거롭고 개발 편의가 낮음. 소량·학습·V2 재사용을 함께 만족하는 A가 균형점.
> **숙고 포인트**: (트레이드오프) A는 상태/DOM 갱신을 손으로 관리(소규모라 부담 적음). / (되돌리기) 나중에 규모가 커지면 React로 이전 가능. / (다른 선택이 유리한 경우) 팀이 이미 React 숙련이고 UI가 커질 예정이면 B.
> **신뢰도**: Medium

[Answer]: A (추천대로 진행)

## 질문 2 — 상태(진행상태) 저장 범위(localStorage 키 설계)
localStorage에 진행 상태를 어떻게 보관할까요?

A) 단일 키에 { noteId: {status, updatedAt} } 맵으로 저장 (파일과 무관하게 noteId 기준 유지)

B) 업로드한 파일별로 분리 저장 (파일 바뀌면 상태도 분리)

X) 기타 (아래 [Answer]: 뒤에 설명해 주세요)

> 🤖 **프론트엔드 엔지니어 권장**: A) 단일 키 + noteId 맵
> **근거**: 각 보기 검토 — noteId(N100xx)가 판독문의 안정적 식별자이므로 A는 같은 판독문을 다시 업로드해도 상태가 이어져 "진행 상황 표기"의 연속성이 자연스럽고 구현·설명이 단순. B는 파일 단위 격리가 필요할 때만 유용하나, 파일 식별·해시 관리가 추가되고 같은 건이 파일마다 상태가 갈라져 혼란. 단일 사용자·소량 전제엔 A가 명확.
> **숙고 포인트**: (트레이드오프) A는 서로 다른 데이터셋이 noteId를 재사용하면 상태가 섞일 수 있음(내부 단일 데이터셋 전제라 무해). / (되돌리기) StatusRepository 계약 뒤에 있으므로 후에 B로 교체 용이. / (참고) V2 서버 저장도 동일하게 noteId 기준이라 일관.
> **신뢰도**: Medium

[Answer]: A (추천대로 진행)

## 질문 3 — 표에서 원문/근거 표시
표의 각 행에서 원문과 근거를 어떻게 보여줄까요?

A) 근거 문장은 항상 표시, 원문 전체는 "펼치기"로 토글 (US-DOC-2/5 충족, 화면 간결)

B) 근거·원문 모두 별도 상세 패널/모달에서 확인

X) 기타 (아래 [Answer]: 뒤에 설명해 주세요)

> 🤖 **프론트엔드 엔지니어 권장**: A) 근거 상시 + 원문 펼치기 토글
> **근거**: 각 보기 검토 — A는 판별 근거(US-DOC-2)를 표에서 바로 보여줘 검증성을 높이고(NFR-5), 긴 원문은 토글로 감춰 목록 가독성을 유지. 컴포넌트 상태가 "행별 펼침 여부"로 단순. B(모달)는 클릭 한 번을 더 요구하고 모달 상태·포커스 관리가 늘어 프로토타입엔 과함.
> **숙고 포인트**: (트레이드오프) A는 근거가 길면 행 높이가 커질 수 있음(요약 길이 제한으로 완화). / (다른 선택이 유리한 경우) 원문을 나란히 비교하는 업무면 B. / (참고: UX 흐름은 제품 책임자 영역) 스토리 US-DOC-2/5가 이미 표 내 확인을 명시.
> **신뢰도**: Medium

[Answer]: A (추천대로 진행)
