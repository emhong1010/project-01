# 비즈니스 규칙 — shared-core (추적 관찰 판별)

> 규칙은 코드 한 곳(FollowUpDetector의 규칙 정의)에 모아 유지보수(NFR-4). 아래는 그 규칙의 설계 명세.

## 결정 사항 (사용자 답변)
- Q1=B: "임상 소견과 함께 판단이 필요합니다"도 추적 관찰 필요로 포함(미탐 최소). 단, `판단형`으로 라벨 구분.
- Q2=A: `[소견]` + `[결론]`만 판별 대상. `[임상정보]`는 제외(오탐 방지).
- Q3=A: 오류 시 예외 throw(호출측이 처리).
- Q4=A: 표준 열 이름 가정.

## 규칙 R1 — 판별 대상 텍스트
- SectionExtractor로 본문을 4개 섹션으로 분리.
- 판별 검사 대상 = `findings`(소견) + `conclusion`(결론) 만.
- `clinicalInfo`(임상정보), `exam`(검사)은 판별에서 제외.
- 섹션 태그가 없으면(비정형): 폴백으로 전체 텍스트를 대상으로 하되 부정 표현 필터 적용(R4).

## 규칙 R2 — 권고형 신호 (category = "권고형")
대상 텍스트에 아래 표현 중 하나라도 포함되면 추적 관찰 필요(권고형):
- "추가 검사 권고"
- "추적 검사를 권고", "추적검사 권고"
- "추가 평가 권고"
- "재검이 필요", "재검사 권고", "재검 필요"
- (확장 대비, 데이터엔 드묾) "추적 관찰", "추적관찰", "추시", "f/u", "follow up", "follow-up"

## 규칙 R3 — 판단형 신호 (category = "판단형")
권고형에 해당하지 않지만 아래 표현이 포함되면 추적 관찰 필요(판단형):
- "임상 소견과 함께 판단이 필요"

## 규칙 R4 — 부정/제외 표현 (오탐 방지)
아래에 해당하면 추적 관찰 필요로 보지 않음:
- "특이 소견 없습니다", "특이 소견 없이 깨끗" 만 있고 권고/판단 신호가 없는 경우 → 필요 아님.
- 신호 표현이 부정문과 결합된 경우: "추적 검사 불필요", "추가 검사 필요 없음", "권고하지 않" → 제외.
- `[임상정보]`에만 있는 "추적 검사"는 규칙 R1에 의해 애초에 검사 대상이 아님(자동 제외).

## 규칙 R5 — 우선순위
1. R4(부정/제외)에 걸리면 → isFollowUpNeeded=false, category=null.
2. R2(권고형) 매칭 → isFollowUpNeeded=true, category="권고형".
3. R2에 없고 R3(판단형) 매칭 → isFollowUpNeeded=true, category="판단형".
4. 그 외 → isFollowUpNeeded=false.

## 규칙 R6 — 근거 추출
- 대상 텍스트를 문장 단위(마침표/줄바꿈 기준)로 분리.
- 매칭된 표현이 포함된 문장을 evidenceSentences에 담음.
- matchedKeywords에는 실제 매칭된 규칙 표현을 담음.

## 규칙 R7 — 추적 시점/기간 추출 (있을 때만)
- 패턴 예: `\d+\s*(개월|주|일|년)\s*(후|뒤|이내|이후)`, "즉시", "추후".
- 첫 매칭을 followUpTiming으로. 없으면 null(이 데이터엔 대부분 null).

## 규칙 R8 — 판독문 필터
- `note_type === "판독문"` 인 레코드만 분석. 그 외(간호기록/경과기록)는 제외하고 excludedCount에 반영.

## 규칙 R9 — 필수 열 검증
- 필수 열: note_type, dept, text (없으면 예외 throw — Q3=A).
- note_id 없으면 행 인덱스를 대체 식별자로 사용.
