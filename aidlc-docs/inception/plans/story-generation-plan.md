# 사용자 스토리 생성 계획

**역할**: 제품 책임자(Product Owner) 관점에서 요구사항을 사용자 중심 스토리로 변환합니다.

이 문서는 (1) 스토리 생성 방법론 계획과 (2) 방향을 정하는 질문으로 구성됩니다. 아래 질문의 `[Answer]:` 뒤에 보기 알파벳으로 답해 주세요. 답변이 확정되면 계획을 실행해 `stories.md`, `personas.md`를 생성합니다.

---

## A. 스토리 생성 실행 체크리스트 (방법론)

- [ ] 페르소나 정의 (사용자 유형·역할·동기)
- [ ] 페르소나별/기능별 스토리 도출 (INVEST 기준: 독립적·협상가능·가치있음·추정가능·작음·테스트가능)
- [ ] 각 스토리에 수용 기준(Acceptance Criteria) 작성
- [ ] 스토리를 V1(서버리스 MVP) / V2(서버 기반)로 구분 태깅
- [ ] 페르소나 ↔ 스토리 매핑
- [ ] stories.md, personas.md 생성 및 검토 요청

---

## B. 확인 질문

## 질문 1 — 페르소나(사용자 유형)
어떤 사용자 유형을 페르소나로 포함할까요? (여러 개 선택 가능)

A) 진료과 담당 의사/판독 검토자 — 자기 과의 추적 관찰 필요 건을 확인하고 진행 상태를 표기

B) 데이터 업로드/운영 담당자 — 판독문 파일을 업로드하고 전체 현황을 관리

C) 부서 관리자/책임자 — 과별 진행률·현황을 한눈에 모니터링

D) 학습자/교육 대상 — 도구의 동작과 구조를 학습(교육 목적)

X) 기타 (아래 [Answer]: 뒤에 설명해 주세요)

[Answer]: d

## 질문 2 — 스토리 구성(분해) 방식
스토리를 어떤 방식으로 조직할까요?

A) 사용자 여정 기반 — 업로드 → 판별 → 과별 확인 → 상태 표기 흐름을 따라 구성

B) 기능 기반 — 시스템 기능(파싱, 판별, 대시보드, 상태관리) 단위로 구성

C) 페르소나 기반 — 사용자 유형별 필요를 중심으로 구성

D) 하이브리드 — 사용자 여정을 큰 축으로 하되 기능/페르소나로 세분

X) 기타 (아래 [Answer]: 뒤에 설명해 주세요)

[Answer]: c
