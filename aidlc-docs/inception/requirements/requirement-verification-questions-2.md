## 질문 1
판독문을 "진료과(과)"로 어떻게 구분하나요?

A) 업로드 파일에 '진료과'(또는 유사) 열이 있어 그 값으로 구분

B) 검사 종류/부위로 과를 매핑 (예: 흉부 CT → 호흡기내과), 매핑 규칙을 별도로 정의

C) 업로드 시 사용자가 과를 직접 선택/지정

D) 위 방식을 혼합 (예: 열이 있으면 사용하고, 없으면 매핑)

X) 기타 (아래 [Answer]: 뒤에 설명해 주세요)

> 🤖 **백엔드 엔지니어 권장**: A) 파일 내 '진료과' 열 사용
> **근거**: 각 보기를 검토하면 — A는 데이터에 이미 있는 사실을 그대로 사용해 규칙 유지보수가 없고 정확, B는 검사→과 매핑 테이블을 계속 관리해야 하고 한 검사가 여러 과에 걸치면 오분류 위험, C는 한 파일에 여러 과가 섞여 있으면 일괄 지정이 불가능, D는 유연하나 두 경로를 모두 구현·검증해야 함. 소량 프로토타입(requirements.md 9번)에서는 A가 가장 단순·정확. 단, D는 A의 안전한 확장이라 차선.
> **숙고 포인트**: (트레이드오프) A는 파일에 과 열이 반드시 있어야 성립 — 없으면 전면 재설계 필요. / (먼저 확인) 실제 업로드 파일에 진료과 열이 존재하는지 샘플로 확인 필요. / (다른 선택이 유리한 경우) 파일에 과 열이 없고 검사종류만 있다면 B 또는 D가 더 적합.
> **신뢰도**: Medium

> 🤖 **소프트웨어 아키텍트 권장**: A) 파일 내 '진료과' 열 사용
> **근거**: A는 판별 로직과 데이터 소스를 느슨하게 결합(입력 데이터가 곧 분류 기준)해 모듈 단순. B는 매핑 규칙이라는 별도 지식 축을 추가해 결합도·변경 영향 증가. C는 UI 입력 상태가 분류에 개입해 응집도 저하. A를 기본으로 하고 부재 시 D로 폴백하는 진화 경로 권장.
> **숙고 포인트**: (되돌리기 어려움) 초기 데이터 모델의 과 식별 필드 선택은 이후 대시보드 집계 구조를 좌우. / (먼저 확인) 과 열 이름 표준화 여부(예: "진료과", "의뢰과", "Dept"). / (다른 선택이 유리한 경우) 데이터 표준이 없으면 D의 폴백 규칙이 필요.
> **신뢰도**: Medium
