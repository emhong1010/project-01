# 사용자 스토리 (User Stories)

**분해 방식**: 페르소나 기반  
**수용 기준 형식**: Given-When-Then  
**버전 태그**: `[공통]` = V1/V2 공유 코어 · `[V1]` = 서버리스 MVP · `[V2]` = 서버 기반  
**INVEST**: 각 스토리는 독립적·협상가능·가치있음·추정가능·작음·테스트가능하도록 작성.

> 상태 값: 대기 / 진행중 / 완료 (기본값: 대기)

---

## P2. 운영/업로드 담당자 (이서연) — 데이터 입력·검증

### US-OP-1 `[공통]` 판독문 파일 업로드
**As** 운영 담당자, **I want** CSV 또는 Excel 파일을 업로드하기를, **so that** 판독문 데이터를 도구로 불러올 수 있다.
- **Given** 유효한 CSV/Excel(`note_id,note_type,note_date,dept,modality,body_part,author_role,text`)이 있을 때
- **When** 파일을 업로드하면
- **Then** 파일이 파싱되어 총 레코드 수가 화면에 표시된다.
- **And Given** `text` 필드에 쉼표·줄바꿈이 포함된 따옴표 셀이 있어도 **When** 파싱하면 **Then** 셀이 깨지지 않고 하나의 본문으로 올바르게 읽힌다.

### US-OP-2 `[공통]` 판독문만 필터링
**As** 운영 담당자, **I want** 판독문 외 기록을 제외하기를, **so that** 분석 대상이 판독문으로 한정된다.
- **Given** 파일에 `판독문/간호기록/경과기록`이 섞여 있을 때
- **When** 파싱이 끝나면
- **Then** `note_type == "판독문"` 인 레코드만 분석 대상이 되고, 제외된 건수가 요약에 표시된다.

### US-OP-3 `[공통]` 형식 오류·누락 열 안내
**As** 운영 담당자, **I want** 잘못된 파일에 대해 명확한 안내를 받기를, **so that** 무엇을 고쳐야 할지 알 수 있다.
- **Given** 파일이 비었거나 필수 열(`note_type`,`dept`,`text`)이 없을 때
- **When** 업로드하면
- **Then** 어떤 문제인지(빈 파일/누락 열 이름)를 한국어 메시지로 안내하고 처리를 중단한다.

## P1. 진료과 담당 의사 / 판독 검토자 (김민준) — 판별·확인·상태표기

### US-DOC-1 `[공통]` 추적 관찰 필요 건 자동 판별
**As** 담당 의사, **I want** 추적 관찰이 필요한 판독문을 자동으로 가려내기를, **so that** 후속 조치가 필요한 건을 놓치지 않는다.
- **Given** 판독문의 `[소견]/[결론]`에 "추적 검사 권고 / 추가 검사 권고 / 재검이 필요 / 추적 관찰 / f-u" 등의 표현이 있을 때
- **When** 판별을 수행하면
- **Then** 해당 건이 "추적 관찰 필요"로 분류된다.
- **And Given** `[임상정보]`에만 "추적 검사"가 있고 소견/결론엔 권고 표현이 없을 때 **When** 판별하면 **Then** 오탐으로 분류되지 않는다(제외).
- **And Given** "불필요/필요 없음" 같은 부정 표현이 있을 때 **When** 판별하면 **Then** 필요 건으로 분류되지 않는다.

### US-DOC-2 `[공통]` 판별 근거 확인
**As** 담당 의사, **I want** 판별 근거 문장/키워드를 함께 보기를, **so that** 규칙 기반 결과를 직접 검증할 수 있다.
- **Given** 어떤 건이 "추적 관찰 필요"로 분류되었을 때
- **When** 그 건을 목록에서 보면
- **Then** 판별의 근거가 된 문장 또는 키워드가 함께 표시된다.

### US-DOC-3 `[공통]` 추적 시점/기간·검사 메타 표시
**As** 담당 의사, **I want** 추적 시점과 검사 정보를 함께 보기를, **so that** 언제·무엇을 후속해야 하는지 파악한다.
- **Given** 본문에 "3개월 후/6개월 뒤/1년 후" 같은 시점 표현이 있을 때 **When** 목록을 보면 **Then** 추적 시점/기간이 표시된다(없으면 공란).
- **And When** 목록을 보면 **Then** 검사 종류(`modality`)·부위(`body_part`)·작성일(`note_date`)이 함께 표시된다.

### US-DOC-4 `[공통]` 내 과의 목록만 확인
**As** 담당 의사, **I want** 내 진료과의 추적 관찰 필요 건만 보기를, **so that** 내 업무에 집중할 수 있다.
- **Given** 데이터가 여러 과로 구성되어 있을 때
- **When** 상단 과 선택 탭에서 특정 과를 선택하면
- **Then** 해당 과의 "추적 관찰 필요" 건만 표로 표시된다.

### US-DOC-5 `[공통]` 원문 확인(요약→펼치기)
**As** 담당 의사, **I want** 필요 시 원문 전체를 보기를, **so that** 맥락을 확인한다.
- **Given** 목록의 각 행이 원문 요약을 보여줄 때
- **When** 해당 행을 펼치면
- **Then** 판독문 원문 전체가 표시된다.

### US-DOC-6 `[V1]` 진행 상태 표기 (로컬 저장)
**As** 담당 의사, **I want** 각 건의 진행 상태를 표기하고 브라우저에 저장하기를, **so that** 새로고침해도 내 표기가 유지된다.
- **Given** 어떤 건의 상태가 "대기"일 때
- **When** 상태를 "진행중" 또는 "완료"로 변경하면
- **Then** 변경이 즉시 반영되고 localStorage에 저장된다.
- **And When** 페이지를 새로고침하면 **Then** 이전에 표기한 상태가 그대로 복원된다.

### US-DOC-7 `[V2]` 진행 상태 표기 (서버 공유)
**As** 담당 의사, **I want** 진행 상태를 서버에 저장해 동료와 공유하기를, **so that** 과 동료들이 같은 최신 현황을 본다.
- **Given** V2 서버에 연결된 상태에서 어떤 건의 상태를 변경할 때
- **When** 상태를 변경하면
- **Then** 변경이 서버에 저장되고, 다른 사용자가 새로고침하면 갱신된 상태를 본다.
- **And** 상태 변경 시 "누가(이름/과)" 변경했는지 최소 정보가 함께 기록된다.

## P3. 부서 관리자 / 책임자 (박지훈) — 현황 모니터링

### US-MGR-1 `[공통]` 전체 요약 대시보드
**As** 관리자, **I want** 전체 요약을 한눈에 보기를, **so that** 전반 현황을 빠르게 파악한다.
- **Given** 파일이 분석 완료되었을 때
- **When** 대시보드를 보면
- **Then** 전체 판독문 수, 추적 관찰 필요 총 건수가 상단에 표시된다.

### US-MGR-2 `[공통]` 과별 추적 관찰 필요 건수
**As** 관리자, **I want** 진료과별 추적 관찰 필요 건수를 보기를, **so that** 어느 과에 후속 조치가 몰려 있는지 안다.
- **Given** 데이터가 여러 과로 구성되어 있을 때
- **When** 대시보드를 보면
- **Then** 과별 "추적 관찰 필요 건수(합계)"가 표로/막대로 표시된다.

### US-MGR-3 `[V2]` 과별 진행 현황 취합
**As** 관리자, **I want** 여러 사용자가 표기한 진행 상태를 과별로 취합해 보기를, **so that** 처리 진척을 모니터링한다.
- **Given** 여러 사용자가 V2에서 상태를 표기했을 때
- **When** 대시보드를 보면
- **Then** 과별로 상태(대기/진행중/완료) 건수가 취합되어 표시된다.

## P4. 학습자 / 교육 대상 (한수아) — 학습·이해 (관찰자)

### US-LRN-1 `[공통]` 한눈에 보이는 폴더 구조
**As** 학습자, **I want** 프로젝트 폴더 구조가 자기설명적이기를, **so that** 어디에 무엇이 있는지 바로 이해한다.
- **Given** 저장소를 처음 열었을 때
- **When** 최상위 폴더를 보면
- **Then** `shared-core/`, `v1-web-serverless/`, `v2-server/` 처럼 이름만으로 역할이 드러나는 구조가 보인다.
- **And** 각 폴더에 역할을 설명하는 간단한 안내(README 또는 주석)가 있다.

### US-LRN-2 `[공통]` 판별 규칙을 한 곳에서 이해·수정
**As** 학습자, **I want** 추적 관찰 판별 규칙이 한 곳에 모여 있기를, **so that** 규칙을 읽고 직접 바꿔볼 수 있다.
- **Given** 공통 코어를 열었을 때
- **When** 판별 규칙(키워드/패턴) 파일을 보면
- **Then** 규칙이 한 곳에 정리되어 있고, 항목을 추가/수정하면 판별 결과에 반영된다.

### US-LRN-3 `[공통]` V1과 V2의 차이 이해
**As** 학습자, **I want** V1과 V2가 코어를 어떻게 재사용하는지 보기를, **so that** 서버리스와 서버 기반의 차이를 배운다.
- **Given** V1과 V2가 같은 공통 코어를 참조할 때
- **When** 두 버전의 코드를 비교하면
- **Then** 동일한 파싱/판별 코어가 재사용되고, 저장/공유 부분만 다르다는 것을 문서/구조로 확인할 수 있다.
